# 01 · 快速上手

> 目标读者：使用蓝天/同方体系模具笔记本（如七彩虹隐星 P15/P16、神舟战神部分型号等），
> 想在 macOS（OpenCore 黑苹果）下读取风扇转速 / 控制风扇的用户。
> 约 15 分钟完成安装验证。

## 前置条件

- OpenCore 引导的 x86_64 macOS（10.15+，实测 15.x）
- 已加载 **Lilu** ≥ 1.6 和 **VirtualSMC** ≥ 1.3（本插件是 VirtualSMC 的插件）
- 编译需要 macOS + Xcode Command Line Tools（`clang`、`xcrun`）

## 1. 获取 kext

**选项 A：用预编译成品**（推荐，无需编译环境）

下载 `dist/ECFanSMC-0.2.1.zip`，解开得到 `ECFanSMC.kext`，直接跳到第 2 节。

**选项 B：自己编译**（想改代码时）

```bash
cd ECFanSMC
./build.sh
```

首次运行会自动下载三个依赖到 `./deps/`（MacKernelSDK、Lilu、VirtualSMC），需要联网；
之后走缓存。产物在 `build/ECFanSMC.kext`。

自检输出应看到 `MH_KEXT_BUNDLE` / `kext bundle`，且**没有未定义符号**。
若符号审计（check-symbols.sh）报错，先看 [04-调试与排错](04-调试与排错.md)。

## 2. 配置 config.plist

把 `build/ECFanSMC.kext` 整个拷到 `EFI/OC/Kexts/`，然后在
`Kernel → Add` 里加一条（用 ProperTree / OCAuxiliaryTools 均可）：

| 字段 | 值 |
|---|---|
| Arch | `Any` |
| BundlePath | `ECFanSMC.kext` |
| Comment | `EC fan bridge (Clevo/Tongfang)` |
| Enabled | `true` |
| ExecutablePath | `Contents/MacOS/ECFanSMC` |
| MaxKernel | 留空 |
| MinKernel | 留空 |
| PlistPath | `Contents/Info.plist` |

依赖顺序：**Lilu → VirtualSMC → ECFanSMC**（ECFanSMC 必须排在 VirtualSMC 之后）。

## 3. 重启验证

```bash
kextstat | grep -i ecfan        # 应看到 ECFanSMC 已加载
```

用 `tools/smc_probe.c` 枚举 SMC 键（编译见文件头注释）：

```
FNum  →  2                # 风扇数量
F0Ac  →  3000~4000 (fpe2) # 风扇1 实时转速，合理范围内随负载变化
F0Mn  →  1000             # 最小转速
F0Mx  →  6500             # 最大转速
TC0D  →  45~90  (sp78)    # CPU 温度
```

> **注意**：重启时务必确认走的是 OpenCore 引导（能看到 OC 菜单或至少 OC 日志有更新）。
> 若 `LauncherOption=Disabled`，系统可能绕过 OC 直接启动，kext 不会加载——
> 这不是编译问题，检查 [04-调试与排错](04-调试与排错.md#kext-没加载)。

## 4. 使用

注册成功后，任何 SMC 风扇工具都可直接使用：

- **Macs Fan Control**：读转速/温度 ✅，Manual 模式拖动调速 ✅
- **TG Pro / Stats / smcFanControl**：✅（本插件完整实现了它们的写后校验语义）
- 命令行：`tools/ecfdump` 可扫描 EC RAM 全表（诊断用）

**交还自动**：工具里切回 Auto，或写 `F0Md=0`。EC 固件会接管温控曲线。

## 5. 安全须知

1. **不要同时开两个风扇控制程序**（例如 Macs Fan Control + 本插件配套工具）——
   它们会按各自的曲线互相覆写目标转速，表现为"调速失灵/自己弹回去"。
2. 异常时（风扇狂转/停转）立即重启，EC 固件会恢复自带温控，不会损坏硬件。
3. 转速上限 `F0Mx` 默认 6500，不确定自己风扇规格就不要往大改。
