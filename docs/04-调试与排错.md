# 04 · 调试与排错

> 测试方法论 + 故障排查表。风扇调速涉及内核与 EC 硬件，
> **方法对了比代码对了更重要**——先把干扰排除，再怀疑自己。

## 一、测试方法论

### 铁律 1：先只读，后写；先小步，后极值

```
① 只读验证：F0Ac 转速合理且随负载变化、TC0D 温度合理
② 单点写入：set 3000（中档），观察 5~10 秒转速是否趋近
③ 阶梯测试：1000 → 3000 → 5000 → 6500，每档停 5 秒
④ 恢复自动：确认 EC 固件接管（转速回落到曲线值）
```

任何一步异常**立即停止**，先查 [排错表](#二排错表)，不要继续加码。

### 铁律 2：测试前排除"抢控制权"的程序

多个风扇控制程序会**互相覆写目标转速**，这是最常见的"调速失灵"假象：

```bash
pgrep -lif "Macs|smcwrite|TGPro|iStat|FanControl"   # 查在跑的风扇工具
```

典型案例（实测）：

```bash
$ ecfanctl set 0 5000 && ecfanctl state
fan0 target=5000        # ✓ 写进去了
$ sleep 3 && ecfanctl state
fan0 target=3858        # ✗ 被 Macs Fan Control 的 smcwrite helper 覆写回它的曲线值
```

**特征**：写入立即生效、几秒后被改回一个"像曲线算出来的值"。
退出其他工具后重测，稳定保持就是这个原因，不是代码问题。

### 铁律 3：区分"写入成功"和"风扇响应"

写入成功 ≠ 转速立刻到位：

- EC 温控有响应滞后（秒级）
- 占空比→转速非线性（低占空比段尤其平缓）
- 目标转速（F0Tg）和实际转速（F0Ac）本来就会有偏差

**看趋势不看瞬时值**，连续采样 3 次以上再下结论。

## 二、排错表

| 症状 | 可能原因 | 解决 |
|---|---|---|
| `FNum=0`，没有任何 F 键 | 插件没加载 | 看下一行 |
| **kext 没加载** | ① 重启没走 OpenCore（`LauncherOption=Disabled` 会绕过）② 加载顺序错（要在 VirtualSMC 之后）③ 未定义符号 | 确认 OC 菜单/日志；查 `Kernel→Add` 顺序；`check-symbols.sh` 审计 |
| 加载了但键没注册 | `start()` 重入/异常提前返回 | 查 `gStarted` 防重入；看 SYSLOG |
| 写返回 `0xe00002c1` NotWritable | 键重复注册（二分查找错乱）或属性没给 WRITE | 枚举全表看键是否重复；检查 addKey 属性 |
| 写返回 `0xe00002c2` BadArgument（用户态） | `SMCKeyData_t` 结构体小于 80 字节 | 按 03 篇坑 8 补齐字段 |
| 写返回 NotPrivileged（用户态） | 写 SMC 必须 root | 用 setuid helper 或 sudo |
| 转速读数离谱（8000+/9999） | 字节序错 / 没套换算公式 | 大端读 + `2156220/raw`（03 篇坑 1） |
| 转速一直 0 | raw=0（风扇停转）或偏移错 | `ecfdump` 看原始字节是否随风扇变化 |
| 点 Manual 立刻弹回 Auto | `F0Tg` 回读没返回写入值 | 目标值缓存（03 篇坑 5） |
| 工具直接说"不支持风扇控制" | 缺 `FS! ` / `F0ID` / `F0Mn·F0Mx` 可写 | 补三个键（03 篇坑 6） |
| **打开某工具就死机** | 内核访问硬件的 API 用错（如 ml_io_write8 当端口 IO） | 反汇编确认指令；03 篇坑 4 |
| 写入成功但风扇不动 | ① 命令码/风扇 index 不对 ② duty 太低 ③ EC 进了保护 | 先试 duty=255（全速）；核对 index 1-based |
| 最低档压不下去 | 代码里的占空比下限钳制 | 放开下限（03 篇坑 7） |
| 调速"粘滞"、拉不动滑块 | UI 每秒用滞后实际转速回写滑块位置 | 跟随目标值而非实际值；松手才提交 |
| 转速能调但和显示对不上 | 常数 2156220 与你的 EC 时钟不符 | 校准（02 篇） |
| EC 无响应（读全 0/FF） | 基址错 / 机型不同布局 | 05 篇重新定位寄存器 |

## 三、内核调试

```bash
# kext 加载状态
kextstat | grep -i ecfan
kmutil showloaded | grep -i ecfan

# 插件日志（SYSLOG("ecfan", ...)）
log show --last boot --predicate 'eventMessage CONTAINS "ecfan"' --info | tail -40

# OC 是否生效（日志文件随版本在 EFI 分区根或 OC 目录）
# LauncherOption=Disabled 时重启可能绕过 OC —— 这是"kext 神秘不加载"的头号原因
```

符号问题自查：

```bash
./check-symbols.sh build/ECFanSMC.kext/Contents/MacOS/ECFanSMC
# 未定义符号会全部列出——内核不导出的（qsort/ml_io_write8 等）必须换实现
nm -u build/ECFanSMC.kext/Contents/MacOS/ECFanSMC
```

## 四、用户态工具

| 工具 | 用途 | 用法 |
|---|---|---|
| `tools/smc_probe.c` | 枚举 AppleSMC 全部键 | 判断键是否存在/重复，验证注册结果 |
| `tools/ecfdump.c` | dump EC RAM 全表（走 EC00..EC07 诊断键） | `./ecfdump -w 2` 持续刷新，看哪个字节随负载变化 |
| `tools/smc_core.c` | SMC 读写核心库 | 读无需特权；写需要 root（可做 setuid helper） |

写 setuid helper 时的安全约束（实测可用的方案）：

- helper 装到 `/usr/local/libexec/`，`chmod 4755` root 属主
- 参数严格校验（fan id ∈ {0,1}，rpm ∈ [0,8000]），不接受任意 key/字节写入
- app 端用 `Process` 调 helper，不要把 root 权限给 GUI 进程本体

## 五、应急处置

| 情况 | 动作 |
|---|---|
| 风扇狂转不停 | 立即 `release`（写 F0Md=0 或发 0x99+0xFF 命令）；不行就重启 |
| 风扇停转 | 断电重启。EC 固件上电自检会恢复自动温控，短时停转不损坏硬件 |
| kext 导致 panic | OC 启动菜单加 `-v`，或临时从 config.plist 禁用该 kext 启动 |
| 系统反复重启进不去 | OC 菜单进恢复模式，挂载 EFI 改 config；或 Windows PE 挂 ESP 修 |

> EC 固件的自动温控是硬件级兜底：**只要交还自动或重启，一切恢复出厂行为**。
> 本插件只触碰风扇/温度寄存器与 0x99 命令，不动键盘/电池/充电等其他 EC 功能。
