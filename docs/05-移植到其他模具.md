# 05 · 移植到其他模具/机型

> 换了一台笔记本（哪怕同品牌同系列），不要无脑套用——**先验证再使用**。
> 本文给出完整流程。走完只需 20~30 分钟，能避免 EC 写坏命令导致风扇失控。

## 一、判断你的模具是否同系

蓝天/同方体系的共同特征（满足前两条即大概率兼容）：

| 检查项 | 怎么看 | 同系特征 |
|---|---|---|
| EC 芯片 | 拆机看丝印 / Windows 设备管理器 | ITE IT55xx（本机 IT5570E-128） |
| DSDT EC 区域 | SysReport 抓 DSDT 反编译 | `OperationRegion (RAM, SystemMemory, 0xFE0B01xx, ...)` |
| 调速软件 | Windows 原厂 | "Control Center"（蓝天/同方方案的通用名） |
| 风扇数 | 实物 | 双风扇为主 |

**已实测机型**：

| 机型 | 模具 | EC | 状态 |
|---|---|---|---|
| 七彩虹隐星 P15 23（海外 EVOL P15 23）`P15 23-HE55D16512A-B` 系 | 蓝天/同方体系公模（12/13 代 H + RTX 40 系，多配置通用） | IT5570E-128 | ✅ 全功能验证 |
| 神舟 TX8 系（`n960kp` 准系统） | 同体系 | IT5570 系 | ✅ `cfc` 验证协议一致 |

> 同一模具不同 CPU/GPU 配置（如 12450H+4050 / 12700H+4060 / 13620H+4060）共用主板
> 与 EC，**kext 直接通用**；个体差异只在 SMBIOS 三件套（每台机器必须唯一）。
> 同系列不同年款（如隐星 P15 24）可能换模具供应商——一律重新验证。

## 二、拿到你自己的 EC 布局

### 步骤 1：SysReport 抓 DSDT（不需要 Windows）

1. `config.plist` → `Misc → Debug → SysReport = true`，重启进 OpenCore
2. ACPI 表导出在 **ESP 分区根目录** `SysReport/`（不是 `EFI/OC/` 下面！）
3. 反编译：`iasl DSDT.aml` → `DSDT.dsl`

### 步骤 2：找 EC 数据区

在 DSDT.dsl 里搜 `EmbeddedControl` 和 `SystemMemory`：

```asl
Device (EC) {
    Name (_HID, "PNP0C09")
    OperationRegion (RAM, SystemMemory, 0xFE0B0100, 0x100)  // ← 数据区
    OperationRegion (EC81, EmbeddedControl, 0, 0xFF)        // ← 命令通道
    Field (RAM, ByteAcc, NoLock, Preserve) {
        // ← 这里逐字段列出偏移，是你的寄存器地图
    }
}
```

记录 Field 里的：温度字段、转速字段（16bit）、占空比字段（8bit）。
**以 Field 定义为准**，不要抄本文的偏移表（温度一项就见过 0x07/0x0B 两种）。

### 步骤 3：只读验证偏移（关键）

装好 kext（只读部分）或用 `ecfdump`，做**变化量验证**：

| 观察目标 | 方法 | 判定 |
|---|---|---|
| 温度偏移 | 待机 vs 烤机各读一次 | 跟着温度涨的字节就是温度寄存器 |
| 转速偏移 | `ecfdump -w 2` 持续刷新，手动改变风扇转速 | 变化的 16bit 对（注意大端） |
| 占空比偏移 | 发一次 duty 命令前后对比 | 对应 8bit 值 = 你写的 duty |

### 步骤 4：校准转速公式

`RPM = 2156220 / raw` 的常数取决于 EC 计数器时钟，同系通用但换芯片可能变。
校准：设全速（duty=255），读 raw，用外部工具（MFC/耳朵/转速贴）估真实转速，
`常数 ≈ rpm × raw`，取多点平均。偏差 < 5% 就不用改。

## 三、找调速命令（如果 0x99 不灵）

按代价从低到高：

1. **直接试 0x99**（同系命中率高）：`set duty`，看 DUT 回读和转速是否响应。
   失败就停，不要乱试命令码。
2. **查 Linux `cfc` / `clevo-indicator`**：同系开源实现，命令码都在源码里。
3. **Windows 侧抓包**（原厂 Control Center 逆向，金标准）：
   - RWEverything 观察 EC RAM 0xF8/0xF9 的 FCMD/FDAT 变化
   - 或 ProcMon/API Monitor 抓 Control Center 的驱动调用
   - 详见历史文档《Windows 抓风扇调速》思路：核心是抓到调速瞬间写进命令通道的字节
4. **ECMD 全表扫描不推荐**：乱发命令可能让 EC 卡死，务必只在有 release/断电
   兜底且知道回滚方法时进行。

## 四、改 kext 的三个配置点

布局不同时只动 `ECFanSMC.cpp` 顶部：

```cpp
#define EC_RAM_PHYS   0xFE0B0100ULL  // ① EC RAM 物理基址（DSDT 里抄）
#define EC_OFF_TMP    0x07           // ② 温度偏移
#define EC_OFF_DUT1   0xCE           //    占空比偏移
#define EC_OFF_RPM1   0xD0           //    转速偏移（16bit）
// ...                        // ③ 风扇数量：ECFanSMC.cpp 的注册循环 + FNum 返回值
```

命令部分（`forceFanDuty` / `releaseFanDuty`）只在换了协议时改。
改完 `./build.sh` → 拷 ESP → 重启，走第一节的验证流程。

## 五、移植验证清单

```
□ DSDT 确认 EC RAM 基址与 Field 偏移
□ ecfdump 只读验证：温度/转速/占空比字节随负载正确变化
□ 转速公式误差 < 5%（对照已知工具或实测）
□ FNum / F0Ac / TC0D 注册正确（smc_probe 枚举无重复键）
□ 单点写入：set 3000，转速趋近目标且稳定保持（排除其他程序覆写）
□ 阶梯测试 1000/3000/5000/6500 两端到位
□ 恢复自动正常（EC 固件接管）
□ 长时间烤机 + 待机各 10 分钟，无死机/风扇失控
```

全部打勾就可以日常用了。任何一项异常，回 [04-调试与排错](04-调试与排错.md)。

## 六、可以安全复用/必须重做的部分

| 项 | 同型号换机 | 同系列换代 | 换模具体系 |
|---|---|---|---|
| ECFanSMC.kext | ✅ 直接用 | ✅ 验证后用 | ⚠️ 按本文重做 |
| EC 协议（02 篇） | ✅ | ✅ 大概率同 | ❌ 重新逆向 |
| SMBIOS 三件套 | ❌ 每台唯一 | ❌ | ❌ |
| USB 映射（UTBMap） | ✅ | ⚠️ 验证 | ❌ |
| config.plist 其余部分 | ✅ | ✅ | ⚠️ 复查 |

> kext 本身不含任何机器身份信息（无序列号/校验绑定），是**模具级通用件**——
> 这也是它可以开源共享的原因。
