## 一、EC 双通道架构

```
┌─────────────────────────────────────────────┐
│                  ITE EC 固件                  │
├──────────────────────┬──────────────────────┤
│  ① EC RAM（数据区）    │  ② 命令通道            │
│  SystemMemory 映射     │  标准 ACPI EC 端口      │
│  0xFE0B0100, 256B     │  0x62(数据) 0x66(状态) │
│  转速/温度/占空比 镜像   │  0x99 调速等私有命令    │
└──────────────────────┴──────────────────────┘
```

- **读数据走 ①**：DSDT 里 `OperationRegion (RAM, SystemMemory, 0xFE0B0100, 0x100)`
  是 EC RAM 的内存映射，直接 mmap 读，无需握手、高效安全。
- **写命令走 ②**：调速不在内存映射里直接写，而是通过端口发私有命令 `0x99`。
  两个通道访问的是**同一块 EC RAM**（偏移一致），只是入口不同。

```c
// DSDT 原文（隐星 P15 23 / IT5570E-128）
\_SB.PC00.LPCB.EC   (_HID: PNP0C09)
  RAM   OperationRegion SystemMemory   0xFE0B0100  0x100   // 数据区
  EC81  OperationRegion EmbeddedControl 0x00      0xFF    // 命令通道
```

## 二、EC RAM 寄存器地图（偏移相对基址）

| 偏移 | 宽度 | 名称 | 说明 |
|---|---|---|---|
| `0x07` | 8bit | TMP | CPU 温度（℃，直接二进制） |
| `0x02` | bit | FAN0/FAN1 | 风扇在位/运转标志（EC 自管，只读参考） |
| `0xCE` | 8bit | DUT1 | 风扇 1 占空比回读（0~255） |
| `0xCF` | 8bit | DUT2 | 风扇 2 占空比回读 |
| `0xD0` | 16bit | RPM1 | 风扇 1 转速计数（**大端**） |
| `0xD2` | 16bit | RPM2 | 风扇 2 转速计数（**大端**） |
| `0xE0` | 16bit | RPM3 | 风扇 3（部分机型） |
| `0xE7` | 8bit | offset | 风扇曲线偏移（见命令 4） |
| `0xF8` | 8bit | FCMD | ECMD 命令寄存器 |
| `0xF9` | 8bit | FDAT | ECMD 数据寄存器 |

> **温度偏移注意**：本机 DSDT Field 中 `TMP` 位于 `0x07`；`cfc` 的资料标注 `0x0B`。
> 同系不同固件会挪位——以你自己 DSDT 的 Field 定位为准（方法见 05 篇）。
> DUT1/DUT2 是 EC 自维护的**回读值**（全 DSDT 只定义不读写），不是控制目标——
> 直接写它们无效，控制要走 0x99 命令。

### 转速换算

```c
raw = (read_ec(0xD0) << 8) | read_ec(0xD1);   // 大端！高字节在前
rpm = (raw == 0) ? 0 : 2156220 / raw;
```

- 常数 `2156220` 来自 EC 转速计数器时钟（`ec-trace.txt` / `fanctrl.c` / Tuxedo
  `ec_access.cc` 三处一致），同系 EC 通用。
- 换算后与 HWiNFO/Macs Fan Control 读数误差 < 3%。
- 校准方法（若怀疑常数不对）：用已知转速点（如全速 255 duty）反推
  `常数 = rpm × raw`，多点平均。

## 三、风扇调速命令（端口 0x62/0x66）

底层是标准 ACPI EC 端口协议：

| 操作 | 命令字 | 步骤 |
|---|---|---|
| 读 EC RAM | `0x80` | `wait(IBF=0)` → `outb(0x80, 0x66)` → `outb(addr, 0x62)` → `wait(OBF=1)` → `inb(0x62)` |
| 写 EC RAM | `0x81` | `wait(IBF=0)` → `outb(0x81, 0x66)` → `outb(addr, 0x62)` → `outb(data, 0x62)` |

状态寄存器 `0x66`：`IBF=bit1`（输入缓冲满，写前必须为 0）、`OBF=bit0`（输出缓冲满，读前必须为 1）。
**每步等待都要带超时**（建议 100 次 × 数 μs），EC 无响应时返回失败而不是死等。

### 命令 1：设置风扇占空比（手动调速）

```
outb(0x99, 0x66)      # 私有命令 0x99「设风扇」
outb(index, 0x62)     # 风扇号：1=风扇1, 2=风扇2   ← 1-based！
outb(duty,  0x62)     # 占空比 0~255（0=停转, 255=全速）
```

### 命令 2：恢复自动调速

```
outb(0x99, 0x66)
outb(0xFF, 0x62)      # 0xFF = release
outb(index, 0x62)     # 风扇号（注意与命令 1 参数顺序相反）
```

### 命令 3：切换风扇模式（备选，直接写 EC RAM）

```
write_ec(0xF9, mode)   # 0x02=auto, 0x04=custom, 0x10=max
write_ec(0xF8, 0xD7)   # 触发标志
```

### 命令 4：风扇曲线偏移

```
write_ec(0xE7, offset)  # 在自动曲线基础上整体加/减
```

> 命令 3/4 来自 `cfc` 逆向，本机未逐一实测；命令 1/2 是实测验证的主路径。
> index **是 1-based**（第一个风扇传 1 不是 0），这是最容易搞错的点。

## 四、ECMD 私有命令通道（DSDT 里的 0xF8/0xF9）

DSDT 的 `ECMD` 方法是固件暴露给 WMI（Windows 厂商 Control Center）的通道：

```
Arg0 Buffer:
  [0]   长度
  [1]   bit7=读回标志, bit0-6=延迟
  [2]   FCMD(→0xF8)  [3] FDAT(→0xF9)  [4] FBUF  [5-7] FBF1-3
→ 写入 EC81 区 Field，读回 6 字节
```

已知 WMI `GCMD` 里的命令码（`0xB8`/`0xCA`/`0xC4` 等）都是查询类；
**风扇调速不在其中**——它是 Control Center 直接走端口发的 0x99，
DSDT 里没写。这也是为什么光看 DSDT 找不到调速命令。

## 五、macOS 内核里的实现要点

```c
// ✅ 端口 IO：内核不导出 inb/outb，用内联汇编
static inline uint8_t ecInb(uint16_t port) {
    uint8_t v; __asm__ volatile ("inb %1, %0" : "=a"(v) : "dN"(port)); return v;
}
static inline void ecOutb(uint16_t port, uint8_t val) {
    __asm__ volatile ("outb %0, %1" : : "a"(val), "dN"(port));
}

// ❌ 千万不要用 ml_io_write8(0x66, cmd) —— 它的第一参数是虚拟地址不是端口号！
//    传 0x66 会被当地址解引用，直接 panic（踩坑实录见 03 篇）
```

内存映射读 EC RAM：

```c
vm_offset_t v = ml_io_map(0xFE0B0100, 0x100);   // 映射物理内存
volatile uint8_t *ecBase = (volatile uint8_t *)v;
uint8_t tmp = ecBase[0x07];                      // 直接偏移读取
```

## 六、协议要点速查

| 要点 | 值 |
|---|---|
| EC 芯片 | ITE IT5570E-128（同系多为 IT55xx） |
| 数据区物理基址 | `0xFE0B0100`（以 DSDT 为准） |
| 调速命令 | `0x99`，参数 index(1-based) + duty(0~255) |
| 恢复自动 | `0x99` + `0xFF` + index |
| 转速公式 | `RPM = 2156220 / ((hi<<8)|lo)`，大端 |
| 状态位 | IBF=bit1 写前查，OBF=bit0 读前查，都要超时 |
